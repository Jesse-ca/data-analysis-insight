# 数据故事结构

## 核心原则

每条洞察都必须遵循 **Situation-Complication-Resolution** 结构，让数据说话。

## 结构定义

### Situation（当前情况）

描述数据展示的事实，用具体数字支撑。

**格式**：
```
当前情况：[具体数字] [指标名称] [时间范围]，[趋势/状态描述]。
```

**示例**：
- 当前情况：2024年Q4销售额为1,200万元，同比增长15%。
- 当前情况：本月客户流失率为5.2%，环比上升0.8个百分点。

### Complication（问题/挑战）

指出数据揭示的问题或挑战。

**格式**：
```
问题：[指标名称] [问题描述]，[影响范围/程度]。
```

**示例**：
- 问题：华东区域销售额同比下降20%，影响整体增长。
- 问题：新客户转化率仅为3%，低于行业平均水平。

### Resolution（建议/行动）

基于数据给出具体、可执行的建议。

**格式**：
```
建议：[具体行动]，预计[预期效果]。
```

**示例**：
- 建议：针对华东区域开展促销活动，预计可提升销售额10%。
- 建议：优化新客户引导流程，预计可将转化率提升至5%。

---

## 组织结构

### 单条洞察

```
洞察标题：[简短描述]

Situation：[当前情况，用数字支撑]
Complication：[问题/挑战]
Resolution：[建议/行动]

置信度：高/中/低
数据来源：[表名/字段]
```

### 多条洞察

```
洞察报告

1. 核心发现
   - Situation：...
   - Complication：...
   - Resolution：...

2. 次要发现
   - Situation：...
   - Complication：...
   - Resolution：...

3. 行动建议
   - 优先级：紧急/重要/长期
   - 负责人：（如能推断）
   - 时间节点：（如能推断）
```

---

## 量化要求

每条洞察必须包含：

| 要素 | 要求 | 示例 |
|------|------|------|
| **具体数字** | 不能用"大概"、"可能" | "销售额为1,200万元" ✅ |
| **对比基准** | 必须有同比/环比/目标 | "同比增长15%" ✅ |
| **影响范围** | 必须说明影响程度 | "影响整体增长" ✅ |
| **建议行动** | 必须具体可执行 | "开展促销活动" ✅ |

---

## 优先级标注

| 优先级 | 标准 | 颜色 |
|--------|------|------|
| **紧急** | 需要立即行动，影响重大 | 红色 |
| **重要** | 需要近期行动，影响较大 | 橙色 |
| **长期** | 需要持续关注，影响较小 | 蓝色 |

## 示例

### 示例1：销售洞察

```
洞察标题：华东区域销售下滑

Situation：2024年Q4华东区域销售额为200万元，同比下降20%。
Complication：华东区域是公司第二大市场，下滑影响整体增长5个百分点。
Resolution：针对华东区域开展为期1个月的促销活动，预计可提升销售额10%。

置信度：高
数据来源：订单明细表，区域维度
```

### 示例2：客户洞察

```
洞察标题：新客户转化率偏低

Situation：本月新客户转化率为3%，低于行业平均水平5%。
Complication：新客户获取成本较高，低转化率导致ROI下降。
Resolution：优化新客户引导流程，预计可将转化率提升至5%。

置信度：中
数据来源：客户表，转化率字段
```

```html
    <h4>洞察标题</h4>

      <strong>Situation：</strong>当前情况描述
    </div>
    <div class="complication">
      <strong>Complication：</strong>问题描述
    </div>
    <div class="resolution">
      <strong>Resolution：</strong>建议行动
    </div>
    <div class="meta">
      <span class="confidence">置信度：高</span>
      <span class="source">数据来源：表名</span>
    </div>
  </div>
  
  <!-- 更多洞察卡片 -->
</section>
```
