# 流程编排模块

## 职责

根据场景复杂度，选择合适的分析流程。

## 流程类型

### 1. PDCA（基础分析）

**适用场景**：
- 数据结构简单（单表或简单多表）
- 用户只要基础分析
- 没有复杂计算需求

**流程**：
```
P（Plan）：需求拆解
  - 核心业务问题
  - 关键指标（KPI）
  - 分析维度
  - 图表选型

D（Do）：数据执行
  - 数据加载与清洗
  - 指标计算
  - 图表生成
  - 报告组装

C（Check）：逻辑自检
  - 总量校验
  - 公式校验
  - 极端值校验

A（Action）：异常处理与行动建议
  - 边缘情况：样本<3条，标注"数据不足，结论仅供参考"
  - 洞察提炼：针对C阶段发现的异常，给出2-3条可执行建议
  - 格式优化：输出风格专业、色调统一、重点突出
  - 基于分析结果生成行动建议
  - 标注优先级（紧急/重要/长期）
```

### 2. PDCAWFR（深度分析）

**适用场景**：
- 数据结构复杂（多表关联）
- 用户要求深度分析
- 需要预测、诊断、模拟

**输出载体（写死）**：
- **静态HTML报告**：数据已嵌入HTML文件，打开即看，无交互
- **不是交互式工具**：不需要用户上传数据
- **AI在线分析**：WFR阶段需要AI实时计算

**流程**：
```
P（Plan）：需求拆解
D（Do）：数据执行
C（Check）：逻辑自检

W（What-if）：情景模拟
  - 设定目标变量
  - 设定自变量（滑块）
  - 模拟不同场景

F（Forecast）：趋势预测
  - 选择预测方法
  - 执行预测
  - 输出置信度

R（Root Cause）：根因诊断
  - 选择诊断方法
  - 分析根本原因
  - 输出判断标准
  - 量化数据支持
  - 反例检验

A（Action）：行动建议
  - 基于W/F/R结论
  - 标注优先级
```

### 3. Tool（计算工具）

**适用场景**：
- 用户需要交互式计算工具
- 多表关联、复杂公式
- 需要实时计算

**流程**：
```
1. 数据上传与解析
2. 配置计算规则
3. 生成交互界面
4. 实时计算与展示
5. 导出结果
```

**⚠️ 重要限制（写死）**：
- Tool模式是**离线HTML工具**，不会联网
- **禁止WFR分析**（WFR需要AI在线分析，Tool模式无法实现）
- **只使用8类固定规则驱动的洞察**（极值/集中度/趋势/异常/关联/偏离/对比/行动建议）
- 如果用户需要WFR分析，必须使用PDCAWFR模式

**代码健壮性要求（写死）**：

1. **Sheet名识别（4层兜底）**
   - 精确匹配规定英文名
   - 中英文别名匹配
   - 按字段内容推断
   - 按位置兜底
   - 全部失败 → 提示"无法识别表"

2. **字段识别**
   - 支持中文别名（如"金额"对应"amount"）
   - 识别不到字段 → 填空值或0，整页不崩

3. **数据类型处理**
   - 数值字段必须是数字（空值或文字转成0）
   - 字符串字段保持原样

4. **公式正确性**
   - 分母为0时显示为空，不能算出无穷大
   - 比率类指标：除法分母为0时显示"-"或"0"

5. **错误处理**
   - 上传/解析/渲染任何环节出错 → 显示红色错误提示
   - 出错不能让整个页面变白屏

6. **降级显示**
   - 图表数据为空 → 显示"暂无数据"
   - KPI没数据 → 显示0，不显示NaN
   - 字段缺失 → 跳过该图表，提示业务人员

**洞察与根因分析（Tool模式 · 离线规则驱动）**：

由于Tool模式是离线HTML工具，无法调用AI，因此洞察和根因分析必须使用**固定的8类规则驱动**：

| 标签 | 方法 | 公式 | 适用场景 |
|------|------|------|----------|
| A. 极值 | 找最高/最低的维度 | max/min(groupBy(field).指标) | 任何有数值对比的场景 |
| B. 集中度 | 帕累托分析 | top1 / total | 识别关键少数 |
| C. 趋势 | 时间维度环比 | (cur - prev) / prev | 有时间序列数据 |
| D. 异常 | 超过阈值项 | 指标 > threshold | 识别异常值 |
| E. 关联 | 多维交叉 | groupBy([d1, d2]) | 多维度交叉分析 |
| F. 偏离 | 实际/目标偏离度 | actual/target - 1 | 有目标值的场景 |
| G. 对比 | 同维度差异 | max ÷ min | 组间差异对比 |
| H. 行动建议 | 基于洞察的下一步 | 诊断 + 优先级 | 任何场景 |

**规则**：
- 至少用5类方法
- 每类至少1条
- 最终≥7条洞察
- 每条洞察：现象 + 数字证据 + 方法 + 置信度 + 建议

## 编排逻辑

**默认规则（写死）**：
- **默认走PDCAWFR**（深度分析）
- **只有用户明确说"生成看板工具"或"做HTML工具"**，才走Tool模式
- PDCA仅用于极简场景（纯数据展示，无分析需求）

**看板 vs 工具（写死）**：

| 概念 | 定义 | 数据来源 | 交互性 | 适用场景 |
|------|------|---------|--------|---------|
| **看板** | 静态报告 | 数据已嵌入HTML | 无交互，打开即看 | "分析数据"、"生成报告"、"做个看板"、"分析一下" |
| **工具** | 交互式工具 | 用户上传Excel | 实时计算，有交互 | "生成看板工具"、"做HTML工具"、"做个交互式工具" |

```
1. 接收场景识别结果和指标推断结果

2. 判断流程类型
   - 用户明确说"生成看板工具"/"做HTML工具"/"做交互式计算工具" → Tool
   - 其他所有情况 → PDCAWFR（默认）

3. 检查用户配置
   - 用户指定流程 → 使用用户指定
   - 未指定 → 使用默认（PDCAWFR）

4. 组装流程配置
   - 流程类型
   - 各阶段参数
   - 特殊规则

5. 输出编排结果
```

**重要**：
- "分析数据"、"生成报告"、"做个看板"、"分析一下" → PDCAWFR（静态HTML报告）
- "生成看板工具"、"做HTML工具"、"做个交互式工具" → Tool（交互式HTML工具）
- 只有明确要求**工具/交互式**，才走Tool

## WFR智能判断规则（写死）

**核心原则**：用户只需上传表格，AI自动完成所有判断。如果用户主动提供了业务目标，AI优先使用用户指定的目标。

### 判断流程

```
用户上传表格
    ↓
AI分析数据特征
    ├── 时间跨度（有几期数据？）
    ├── 维度数量（有几个分析维度？）
    ├── 数值波动（数据波动大吗？）
    └── C阶段异常（自检发现了什么问题？）
    ↓
检查用户是否主动提供业务目标
    ├── 用户提供了 → 优先使用用户指定的目标
    └── 用户未提供 → AI自动推断
    ↓
智能判断WFR
    ├── F：有≥2期数据 + 有时间维度 → 执行F
    ├── R：C阶段有异常 / 维度≥2 → 执行R
    └── W：C阶段有异常 + 维度≥3 → 执行W
         （AI自动把异常转化为模拟目标，或使用用户指定目标）
    ↓
执行分析
    ↓
输出报告
```

### F（Forecast）判断标准

**适合F的场景**：
- 有历史数据（≥2期）
- 有时间维度（日期字段）

**判断逻辑**：
```
IF 用户明确指定预测目标 → 执行F（使用用户指定目标）
ELSE IF 有≥2期数据 AND 有时间维度 → 执行F（AI自动推断目标）
ELSE → 跳过F
```

**AI自动完成**：
- 预测目标：从数据中推断（如"预测下月销售额"）
- 预测方法：根据数据特征选择（移动平均/指数平滑/线性回归）

### R（Root Cause）判断标准

**适合R的场景**：
- C阶段发现异常（极端值、异常波动）
- 数据维度足够（≥2个维度用于交叉分析）

**判断逻辑**：
```
IF 用户明确指定诊断问题 → 执行R（使用用户指定问题）
ELSE IF C阶段有异常 → 执行R（AI自动推断问题）
ELSE IF 维度≥2 → 执行R（AI自动推断问题）
ELSE → 跳过R
```

**输出条数（写死）**：
- **每次R分析输出5-8条根因**
- 每条针对一个异常值或一个KPI
- 每条必须包含：方法选择依据、判断标准、量化数据、反例检验、边界条件、置信度

**AI自动完成**：
- 业务问题：从C阶段异常中推断（如"为什么耗材占比低"）
- 分析方向：从数据维度中选择（如"渠道效率"、"产品结构"）
- 根因方法：根据问题特征选择（5 Whys/鱼骨图/帕累托等）

### W（What-if）判断标准

**适合W的场景**：
- 有明确的业务目标（KPI）需要模拟
- 数据维度足够（≥3个维度用于分组推演）

**判断逻辑**：
```
IF 用户明确指定业务目标 → 执行W（使用用户指定目标）
ELSE IF 有KPI异常且维度≥3 → 执行W（AI自动推断目标）
ELSE → 跳过W
```

**W分析目标（写死）**：
- **W分析针对KPI，不是异常值**
- 模拟不同场景下的KPI变化（如"如果销售额提升10%会怎样"）
- 关注变量：从数据维度中选择（如渠道权重、增长率）
- 推演基准：用当前数据作为基准

**用户指定优先**：
- 如果用户主动提供了业务目标（如"模拟京东销售提升20%的效果"），AI直接使用
- 如果用户未提供，AI自动从数据中推断KPI目标

**示例**：
| 用户输入 | AI处理 |
|----------|--------|
| "模拟京东销售提升20%的效果" | 直接使用用户指定目标 |
| 未提供 | AI发现某KPI异常 → 自动推断模拟目标 |

## R阶段：根因分析方法（写死）

### 可选方法

| 方法 | 适用场景 | 说明 |
|------|----------|------|
| **5 Whys** | 单一问题根因 | 连续追问5个为什么 |
| **鱼骨图** | 多因素分析 | 按人/机/料/法/环分类 |
| **价值树** | 指标拆解 | 指标层层分解 |
| **下钻归因** | 维度交叉分析 | 按维度逐层深入 |
| **帕累托分析** | 关键少数 | 80/20法则 |
| **时间序列归因** | 趋势异常 | 按时间维度分析变化原因 |
| **组合维度归因** | 多维交叉 | 多维度交叉定位根因 |

## W阶段：情景模拟计算逻辑（写死）

### 业务输入

**必填**：
- 业务目标：如"提升销售额10%"
- 关注变量：如"客户增长率"、"客单价变化"
- 推演基准：如"Q2 4-6月"

**选填**：
- 分组维度：如"渠道"、"区域"
- 比较指标：如"销售额"、"销量"
- 各组权重：如"直销50%/经销20%/电商20%/政企10%"

### 计算逻辑

```
1. 按[分组维度]分组，每组计算[比较指标]
2. 计算各组基础乘数 = 该组指标 ÷ 整体平均
3. 业务人员调权重后：
   加权后系数 = 基础乘数 × (权重 ÷ 平均权重)
4. 模拟各组 = 基准各组 × (1 + 自变量) × 加权后系数
5. 模拟总额 = 各组模拟加总
```

### 滑块默认值

- 关注变量（如客户增长率）：默认 +10%
- 比较指标（如客单价）：默认 +5%
- 各组权重：默认各 25%（平均分配）

### 输出要求

- 新区块标题："🎯 情景模拟器"
- 滑块实时联动（包括权重调节滑块）
- 纯 JavaScript，禁外部库
- 视觉规范：主色、卡片圆角 8px

## F阶段：偏离类规则（写死）

**F偏离类**：实际/目标偏离度 = actual/target - 1

**跳过规则**：
```
IF 场景没有"目标/计划"概念 → 跳过F偏离类
ELSE → 计算偏离度
```

**示例**：
- 有目标：销售额目标100万，实际80万 → 偏离度 = -20%
- 无目标：客服响应时间（无目标值）→ 跳过F偏离类
| **帕累托分析** | 关键少数 | 80/20法则 |
| **下钻归因** | 维度下钻 | 按维度逐层下钻 |
| **时间序列归因** | 时间趋势 | 时间维度分析 |
| **组合维度归因** | 多维度交叉 | 维度组合分析 |

### 方法选择规则

```
1. 选择方法时，必须说明：
   - 为什么选这个方法
   - 依据是什么
   - 数据特征是什么

2. 输出格式：
   - 结论 + 具体数字
   - 方法名称
   - 选择理由
   - 数据来源
```

## F阶段：趋势预测方法（写死）

### 可选方法

| 方法 | 适用场景 | 说明 |
|------|----------|------|
| **移动平均** | 数据波动小，无明显趋势 | 简单易懂，适合短期预测 |
| **加权移动平均** | 近期数据更重要 | 给近期数据更高权重 |
| **指数平滑** | 数据有趋势，近期数据更重要 | 加权平均，近期权重高 |
| **线性回归** | 数据有明显线性趋势 | 拟合直线，外推预测 |
| **简单同比/环比** | 有同期数据可对比 | 与去年/上期对比 |
| **季节性分解** | 数据有周期性 | 分解趋势+季节+残差 |

### 方法选择规则

```
1. 数据量 < 6期 → 移动平均（简单可靠）
2. 数据有趋势但无周期 → 指数平滑
3. 数据有明显线性趋势 → 线性回归
4. 有去年同期数据 → 简单同比
5. 有年度周期 → 季节性分解
6. 选择时必须说明为什么选这个方法
```

### 量化数据支持规则

```
每条根因必须包含：
1. 具体数字（不能用"大概"、"可能"）
2. 数据来源（基于N行数据）
3. 计算过程（分子/分母）
4. 对比基准（同比/环比/目标）
```

### 反例检验规则

```
每条结论必须包含：
1. 反例检验：举出反例或限制条件
2. 边界条件：什么情况下结论不成立
3. 置信度：高/中/低
```

## C阶段：自检逻辑（写死）

### 总量校验

```
校验规则：
1. 各分类加总 = KPI总计
2. 各维度加总 = KPI总计
3. 如不相等，说明数据有问题
```

### 公式校验

```
校验规则：
1. 分子分母是否倒置
2. 单位是否正确
3. 小数位数是否合理
```

### 极端值校验

```
校验规则：
1. 是否有异常极值
2. 极值是否影响结论
3. 是否需要处理极值
```

## 错误处理

- 流程类型不明确 → 使用PDCA
- 阶段执行失败 → 跳过该阶段，继续后续
- 用户配置冲突 → 以用户配置为准
