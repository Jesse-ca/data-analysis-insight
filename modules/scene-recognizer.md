# 场景识别模块

## 职责

AI分析用户上传的Excel，自动识别数据场景。

## 识别维度

### 1. 数据结构识别

| 结构 | 特征 | 示例 |
|------|------|------|
| 单表 | 1个Sheet，字段完整 | 销售明细 |
| 多表 | 多个Sheet，有外键关联 | 订单+客户+产品 |
| 双表 | 2个数据源，需要比对 | 报关数据 vs 主数据 |

### 2. 业务场景识别（通用场景）

**不限定具体场景**，让AI根据数据特征自由判断。

AI识别时参考以下维度：

| 维度 | 识别特征 |
|------|----------|
| **数据结构** | 单表/多表/双表 |
| **字段特征** | 日期类、数值类、分类类、ID类 |
| **业务关键词** | 从字段名推断业务含义 |
| **行业特征** | 从指标名称推断行业 |
| **用户意图** | 从用户描述推断场景 |

### 3. 字段类型识别

| 类型 | 特征 | 处理 |
|------|------|------|
| 日期 | 包含"日期"、"时间"、"date"、"月"、"年" | 时间序列分析 |
| 数值 | 包含"金额"、"数量"、"率"、"值" | 聚合计算 |
| 分类 | 包含"类型"、"渠道"、"区域"、"等级" | 分组分析 |
| ID | 包含"id"、"编号"、"代码" | 关联字段 |
| 文本 | 其他字段 | 描述性字段 |

## AI识别流程

```
1. 读取Excel，获取Sheet列表和字段

2. 分析每个Sheet的字段特征
   - 字段名推断类型
   - 数据样本验证类型
   - 统计数据规模（行数、字段数）

3. 识别表间关系
   - 找相同字段名（潜在外键）
   - 验证字段值是否匹配
   - 确认关联关系

4. 综合判断场景（让AI自由推断）
   - 数据结构 → 单表/多表/双表
   - 字段特征 → 推断业务场景
   - 行业特征 → 推断行业领域
   - 用户意图 → 结合用户描述

5. 输出识别结果
```

## 数据质量识别（强制执行）

在场景识别阶段，必须执行数据质量检查，输出质量报告。

### 检查维度

| 维度 | 检查内容 | 判断标准 |
|------|----------|----------|
| **完整性** | 空值比例 | >5% 标记为问题 |
| **有效性** | 无效数据（负数、异常值） | 检查业务逻辑 |
| **一致性** | 数据格式不统一 | 如日期格式混乱 |
| **准确性** | 明显错误 | 如金额为负 |
| **数据量** | 行数是否足够分析 | <10行标记为不足 |

### 质量问题分类

| 级别 | 说明 | 处理方式 |
|------|------|----------|
| **严重** | 数据不完整，影响分析 | 提示用户补充数据 |
| **警告** | 数据质量有问题，可能影响结论 | 标注在报告中 |
| **提示** | 数据质量一般，可继续分析 | 记录但不影响输出 |

### 输出格式

```json
{
  "dataQuality": {
    "completeness": 0.95,
    "validity": 0.90,
    "consistency": 0.85,
    "totalRows": 59,
    "validRows": 59,
    "issues": [
      {
        "type": "warning",
        "field": "台数合计",
        "description": "部分行台数合计为0",
        "count": 10,
        "impact": "可能影响销量分析准确性"
      }
    ]
  }
}
```

### 质量报告在HTML中的展示

在HTML报告中增加"数据质量"卡片，展示：
- 数据完整性得分
- 数据有效性得分
- 发现的问题列表
- 对分析结论的影响说明

## 错误处理

- 文件格式错误 → "请上传.xlsx文件"
- Sheet为空 → "Sheet无数据"
- 无法识别 → "数据结构不明确，请补充说明"
- 数据质量问题 → 在报告中标注，不影响分析输出
